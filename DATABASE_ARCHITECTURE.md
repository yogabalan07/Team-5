## RELATIONSHIPS (Application-Managed, No FK Constraints)

| Source | Column | Target | Relationship |
|--------|--------|--------|-------------|
| `purchases` | `supplier_id` | `suppliers.id` | Many-to-One (logical) |
| `purchase_items` | `purchase_id` | `purchases.id` | Many-to-One (logical) |
| `purchase_items` | `item_id` | `items.id` | Many-to-One (logical) |
| `sales` | `customer_id` | `customers.id` | Many-to-One (logical) |
| `sale_items` | `sale_id` | `sales.id` | Many-to-One (logical) |
| `sale_items` | `item_id` | `items.id` | Many-to-One (logical) |
| `stock_reports` | `item_id` | `items.id` | Many-to-One (logical) |

**Note:** The application does NOT use database foreign key constraints. Relationships are managed at the Java/JPA level using `@Column` with explicit ID fields, not `@ManyToOne` with `@JoinColumn`.

---

## ID GENERATION

All 9 tables use `BIGINT GENERATED BY DEFAULT AS IDENTITY` for primary keys.

No soft delete columns. Records are hard-deleted when removed.
